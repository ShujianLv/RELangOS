为何现在做新 OS

内存安全、端侧 AI、能力模型与多设备协同同时成熟；旧栈仍按「人点 App、单机权限」设计。

新常态

  • 代理代替人手调用相机、任务、工具
  • 手机 · 车机 · 地面站 · 机载盒一体作业
  • 野外 / 产线要热升级，少整机重刷
  • 推理在 NPU，策略在可审计的 Actor 里

RELang 的回答

  • Erlang 式监督树升为 OS 原则
  • Rust 实现 RVM，保证运行时内存安全
  • 能力句柄替代粗粒度环境权限
  • 垂直设备优先，不做无边界的手机大战

五大差异化

  • AI 代理原生 — 代理是被监督进程；工具 = 消息；权限 = 能力；配额与审计内建；可对接 MCP。
  • 多设备即一台机器 — 安全会话集群；本地与远端同一套消息语义。
  • 永不重启（目标叙事） — 子树恢复 + 组件热升级，降低整机重启依赖。
  • 结构性安全 — Rust 运行时、无环境权限、不可信原生进隔离域。
  • 无全局 GC 卡顿 — 每进程独立堆；UI 路径不受全局停顿绑架。

架构鸟瞰

应用 / 代理（Gleam · Elixir · Erlang）
        │  消息 · 能力 · Intent
系统监督树（framework 服务）
        │
   RVM（BEAM 语义 · Seed · Dist · Dirty）
        │
原生层：合成器 · UI 引擎 · Agent · HAL · 加速器
        │
Linux（前期）· cgroup / 异步 I/O / 可选隔离

不自研芯片驱动；前期复用主线 Linux / 厂商 BSP。无设备或无宿主时返回诚实失败，不编造成功。

垂直场景

多设备个人集群

启动器、设置、声明式 UI、应用包与跨设备会话 — 长期故事线。

工业与物流终端

监督树 + 热升级 + 能力审计，适合野外与产线运维。

AI 硬件

代理与加速器统一 ABI；任务 OS 与算力板解耦。

现场伴飞 / 伴控（FieldCompanion）

无人机与机器人共用同一垂直面：RELang 做任务与协同，硬实时留在外部。

RELang外部栈
作业编排、围栏意图、mesh、OTA、感知推理飞控内环、伺服、安全 PLC
MAVLink / ROS 2 宿主桥（意图）PX4 / ArduPilot、运动控制器

合适位置

  • 机载伴飞电脑、地面站、编队协同
  • 工业臂旁智能盒、仓内 AMR / 巡检移动机器人
  • 不替代飞控固件或 EtherCAT 主站

端侧 AI

  • 系统代理：工具注册、确认、配额、审计
  • CPU / GPU / NPU / TPU 统一为加速器类 — 应用不绑厂商 API 字符串
  • 大张量走句柄；推理在隔离域，避免拖死 UI 帧钟
  • 外部编程助手可走 MCP / LSP 适配；产品不自研 Codex
